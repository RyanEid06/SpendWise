# WP37 Implementation Plan

> Execute the approved work continuously using independent domain agents and coordinator integration. The owner explicitly authorized starting implementation and delegated model choices; no additional design approval is required.

**Goal:** Finish the approved WP37 localization, native authentication, RTL, backup, AI progress and Statistics hardening without weakening WP36.

**Architecture:** Extend existing services and shared UI components. Semantic authentication actions map to localized prompt copy; existing financial facts remain server-rendered. Restore preferences are opt-in; All-Time disclosure affects presentation only.

**Tech Stack:** React19, TypeScript, Capacitor8, Android Java/API24+, AndroidX biometric1.1.0, Node22, Playwright.

**Spec:** `docs/WP37_SPEC.md` and `docs/WP37_ORIGINAL_PROMPT.md` (all 60 parts).

## Global constraints

- Preserve WP36 provider/runtime/security/financial/draft behavior, optional descriptions and V1/V2/V3 compatibility.
- No merge/deploy/tag/public release/version bump/branch deletion. Private signed validation build uses existing metadata.
- Test meaningful changed behavior RED then GREEN; do not create brittle source-text assertions or weaken gates.
- Keep exact command/results and device limitations in task reports and the progress ledger.
- Agents own disjoint files; coordinator integrates cross-cutting harness/scripts and performs combined validation.

## Review focus

- Stale native callbacks after true background timeout; no protected data reopening.
- Credential recovery must actually authorize Keystore on supported APIs; UI success alone is insufficient.
- Restore setting failure and failed rollback must not masquerade as successful restoration.
- Sparse/partial histories, missing months, zero baseline and tied categories must not invent trends.
- Old/new server/client response compatibility and UI truncation under Arabic/French/large text.
