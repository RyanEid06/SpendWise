## Design and sequence

1. Reproduce lost unfinished fields after restart; add behavioral regressions.
2. Store one editor snapshot and bounded photo payloads in the existing SQLCipher
   database. Draft photo bytes stay in encrypted database rows until Save, avoiding
   private-media orphan cleanup races. Reuse existing encrypted media for saved photos.
3. Serialize writes on every meaningful state change, without a debounce. Preserve
   raw amount text, description/merchant, category identity, date, note, Edit identity,
   attachment removals and optional AI photo/result/interruption state.
4. Recover after authenticated startup/unlock; clear on intentional Cancel/Back,
   atomic successful Save, financial reset, or deletion of the edited expense.
   Background/destruction and picker cancellation never imply discard.
5. Run build, unit, browser/component and targeted actual Android process-death gates;
   inspect artifacts for failures; request one final independent branch review.
6. Commit/push and create an unmerged draft PR against the integration branch.

Ruling: Work in the explicitly supplied clean checkout on the requested new branch;
the user specified this workspace and autonomous execution. No extra checkout is needed.

Ruling: Browser recovery also encrypts its snapshot (AES-GCM with a nonextractable
IndexedDB key); it is browser-origin protection, not Android Keystore security.
Android snapshots and photos use SQLCipher under the existing Keystore session gate.
